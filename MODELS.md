## Model (v4)

These are openWakeWord-style classifiers. Input is `[batch, 16, 96]`, the last 16 embeddings ≈ 1.28 s of audio.
Output is `[batch, 1]`, a sigmoid score.
Layers: `Flatten → Linear(1536,128) → LayerNorm → ReLU → Dropout(0.3) → Linear(128,128) → LayerNorm → ReLU → Dropout(0.3) → Linear(128,1) → Sigmoid`, exported with ONNX opset 13.

In the app, `OwwPipeline` streams 80 ms frames into `WakeDecider`, which has these tuned defaults:

| Setting | Value | Meaning |
|---|---|---|
| `DEFAULT_GROK_THRESHOLD` | 0.7 | "hey grok" score threshold |
| `DEFAULT_BOT_THRESHOLD` | 0.9 | "hey grok bot" score threshold |
| `DEFAULT_GROK_PATIENCE` / `DEFAULT_BOT_PATIENCE` | 5 / 5 | consecutive 80 ms frames above threshold before a model counts as firing (~400 ms) |
| `botWaitFrames` | 8 | after "hey grok" fires, wait ~640 ms for "hey grok bot" (prefix problem) |
| `refractoryFrames` | 12 | ignore ~1 s after a detection |

Patience removes most one-off spikes on continuous speech. It adds about 0.4 s of latency, and "hey grok" waits a further 0.64 s for the bot model.

## Training data (100 % synthetic, generated by `training/run.sh`, never committed)

- **TTS:** [Piper](https://github.com/OHF-Voice/piper1-gpl) (`piper-tts` 1.8.0, GPL-3.0, tool only) with:
  - `en_US-libritts_r-medium`, 904 speakers, trained on [LibriTTS-R](http://www.openslr.org/141/) (CC BY 4.0)
  - `en_GB-vctk-medium`, 109 speakers, trained on [VCTK](https://datashare.ed.ac.uk/handle/10283/3443) (CC BY 4.0)
  - `en_US-l2arctic-medium` was excluded because its dataset is CC BY-NC.
- **Speakers:** the first 85 % of speaker IDs are for training. The last 15 % are **held out**, and every number below uses only them.
- **Clip data:** isolated 2 s clips.
  - 5,000 positives per phrase.
  - 12,000 confusable negatives ("hey google", "hey rock", "hey grog", "a grok", "grok bot", …), end-aligned and randomly placed.
  - 6,000 random-word sentences and 1,500 synthetic noise clips.
  - Bot model only: 9,000 "hey grok"-alone negatives.
- **New in v4:**
  - **Hard negatives from continuous audio:** 4 h of continuous synthetic speech from training speakers (`stream_train2–5.py`), with 15 % confusables, random gaps and background noise. That's 180,126 sliding windows, all used as negatives.
  - **Mining pass:** pass 1 trains on everything. Pass 2 retrains with 20× weight on stream windows that pass 1 scored ≥ 0.1.
  - **In-context positives** (`pos_stream_train.py`): 1,000 utterances per phrase in which the wake word follows a sentence. The 5 windows ending 0–0.4 s after the wake word are positives (about 5,000 per phrase). Without this, patience hurt "hey grok" recall badly.
- **Augmentation:**
  - Piper length, noise and noise_w randomization
  - synthetic reverb
  - white, pink, brown, hum noise at 5–30 dB SNR
  - random gain
- **Training:** AdamW lr 1e-3, weight decay 1e-2, cosine schedule, batch 512. Pass 1 is 25 epochs and pass 2 is 40. Negative weights: clips 3×, stream windows 1× (20× if hard). About 15 minutes on 8 CPU cores.

## Metrics: before (v1) → after (v4)

All numbers come from held-out speakers and synthetic audio. "Stream" is a 1 h held-out continuous stream with 15 % confusable phrases. "Plain speech" is a 0.5 h held-out stream with no confusables.

**App-level (what the user experiences), measured end to end with the exact `WakeDecider` logic** (`training/decider_eval.py`; positives are 300 held-out utterances per phrase, each spoken after a sentence):

| | v1 (threshold 0.5, no patience) | **v4 (shipped defaults)** |
|---|---|---|
| "hey grok" recall in context | n/a (not measured with decider) | **91.7 %** |
| "hey grok bot" recall in context | n/a | **99.3 %** (0.7 % reported as plain "hey grok") |
| False accepts / hour, plain speech | 78–80 per model | **0** |
| False accepts / hour, confusable stream | 66–86 per model | **3** |

**Per-model, no patience, threshold 0.5:**

| | v1 hey_grok | v4 hey_grok | v1 hey_grok_bot | v4 hey_grok_bot |
|---|---|---|---|---|
| Recall (1,250 held-out end-aligned clips) | 95.3 % | 91.4 % | 98.8 % | 99.0 % |
| False accepts, confusable clips | 6.5 % | 3.3 % | 0.07 % | 0 % |
| False accepts/hour, stream | 66 | 20 | 86 | 5 |
| False accepts/hour, plain speech | 78 | 4 | 80 | 10 |

**About the target of < 2 false accepts/hour with ≥ 90 % recall:** it's met on plain speech (0/h) but **not quite on the confusable-heavy stream (3/h)**.
- Many of those confusables are near-misses like "grok", "a grok" and "grok bot". Whether "grok bot" should wake the app is a judgment call.
- The streams are short (1.5 h total held out), so one event changes the rate by 1–2 per hour. Treat these as rough estimates.
- Other tuned options from the grid (`training/decider_grid.json`):
  - patience 4/4 at 0.5/0.8 gives 95.3 % / 99.3 % recall and 6 FA/h on the confusable stream.
  - Higher patience reduces false accepts further but drops "hey grok" recall below 90 %.
- **Synthetic-only data:** real microphones, accents, rooms, TV and music will differ, and nothing has been measured on a device yet.
- Next steps:
  - more hours of continuous negatives, ideally real speech with a permissive license (for example Common Voice CC0 or LibriSpeech CC BY 4.0)
  - real-device recordings for evaluation

## Licenses and redistribution

- **Our keyword models** were trained only on audio generated from voices whose data is CC BY 4.0, which allows redistributing derived works with attribution (given above).
  **Flag:** Piper's `libritts_r` and `vctk` voices were fine-tuned from Piper's `lessac` voice. The Lessac/Blizzard 2011 data behind it has non-commercial terms.
  Whether that carries through synthetic samples into a classifier is legally unclear. Review it before any commercial use.
- **melspectrogram.onnx / embedding_model.onnx:** the openWakeWord code is Apache-2.0, but its README says *"all of the included pre-trained models"* are CC BY-NC-SA 4.0.
  The embedding model is a re-implementation of Google's Apache-2.0 `speech_embedding`, and the mel model is a fixed DSP transform, yet upstream doesn't explicitly exempt either one.
  **Flag:** treat both as **possibly CC BY-NC-SA 4.0 (non-commercial, share-alike)** until upstream confirms otherwise. That's fine for this personal open-source project, but check before any commercial release.
- ONNX Runtime: MIT. Test clips in `app/src/test/resources/clips` were generated with the same CC BY 4.0-derived voices.

## Retrain

```bash
cd training && ./run.sh   # resumable; creates a venv, downloads voices and feature models, generates data, trains v4, evaluates, copies models to assets
```

`training/metrics.json` (v4 per-model), `training/metrics_v1.json` (v1) and `training/decider_grid.json` (app-level grid over thresholds and patience) hold the raw numbers.

The generated datasets (`training/features`, `voices`, `models`, `out`, `*.npy`) are gitignored and never committed.
